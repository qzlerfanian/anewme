# اصلاح RR و قیمت نماد — نسخه 3.2.1

RR نهایی قبل از اعتبارسنجی با `Entry`، `Stop Loss` و `Take Profit` نرمال‌شده بر اساس `symbol_tick_size` محاسبه می‌شود؛ اگر Tick Size موجود نباشد، Digits واقعی نماد استفاده می‌شود. همان قیمت‌های نرمال‌شده برای اعتبارسنجی جهت، RR، محاسبه حجم و ثبت ردیابی استفاده می‌شوند. Snapshot MT5 اکنون Digits واقعی نماد را هم ذخیره می‌کند.

برای BUY ترتیب `SL < Entry < TP` و برای SELL ترتیب `TP < Entry < SL` الزامی است. فاصله ریسک صفر یا RR غیرقابل‌محاسبه ایمن رد می‌شود.

حداقل RR پیش‌فرض `1.80` است و با `MINIMUM_REWARD_RISK_RATIO` قابل تنظیم است. اگر Calculated RR معتبر ولی کمتر از حداقل باشد، نتیجه TRADE وارد WATCH اطلاعاتی می‌شود و با دلیل دقیق نشان می‌دهد که RR هنوز به حداقل نرسیده است؛ این مورد فقط زمانی رخ می‌دهد که هیچ خطای ایمنی دیگری وجود نداشته باشد. اگر خود سناریو قبل از رسیدن به حداقل RR منقضی/باطل شود، چرخه واچ طبق منطق قبلی NO_TRADE می‌شود. حداقل RR به‌تنهایی Entry را مجاز نمی‌کند؛ تمام شروط اصلی استراتژی همچنان لازم‌اند.

RR اعلام‌شده API فقط برای کنترل ثبت می‌شود. اختلاف کوچک اگر `abs <= 0.10R` یا درصد اختلاف `<=5%` باشد، ردکننده نیست و Calculated RR مرجع باقی می‌ماند. اختلاف بزرگ با دلیل دقیق رد می‌شود.

در قیمت‌گذاری، منبع ثابت Snapshot استفاده می‌شود: Bid/Ask و Spread همان منبع فعلی ربات‌اند و بین تولید/اعتبارسنجی/بازبینی جایگزین نمی‌شوند. این نسخه منطق انتخاب Entry یا سمت سفارش را تغییر نمی‌دهد.

در زمان کندل، MT5 با حذف position صفر، کندل در حال تشکیل را کنار می‌گذارد و برای کندل‌های باقی‌مانده `timestamp_semantics=open_time` و `closed_confirmed=true` ذخیره می‌کند. بنابراین timestamp 12:20 به معنی شروع کندل است؛ کندل 12:15 که close_time آن 12:20 است فقط وقتی وارد تحلیل می‌شود که feed آن را از بخش نهایی‌شده برگردانده باشد.
